🔴 Problema 1: tritos_compress NO soporta carpetas
text
exit code: 1
/tmp/carpeta_prueba.trc5: No such file or directory
El binario solo acepta archivos sueltos, no directorios. Con a.txt funciona perfectamente:

text
Compressed: 11 -> 44 bytes (0.25x, -300.0% saved)
exit: 0
Con la carpeta, falla con código 1. No hay forma de que la UCA comprima carpetas tal como está el binario.

🔴 Problema 2: El comando de la UCA está ROTO
Fíjate en este error que aparece al reiniciar Thunar:

text
xfce4-terminal: Opción desconocida «-c»
xfce4-terminal: Opción desconocida «-c»
xfce4-terminal: Opción desconocida «-c»
Tu UCA usa:

xml
<command>xfce4-terminal --hold -e bash -c '...'</command>
Pero xfce4-terminal NO acepta -c como opción directa, ni --hold -e de esa forma. Las opciones correctas son:

xfce4-terminal --hold -x bash -c '...' (con -x, no -e)

O mejor: xfce4-terminal --hold -e "bash -c '...'" (todo entre comillas)

Por eso nunca se ejecuta nada cuando haces click en Tritos. La terminal ni siquiera se abre.

🔴 Problema 3: El binario NO comprime, EXPANDE
text
Compressed: 11 -> 44 bytes (0.25x, -300.0% saved)
11 bytes → 44 bytes. Cuadruplica el tamaño. El "formato ternario ancestral" es un experimento, no un compresor real. Añade cabecera TRC5, CRC32 y codificación ternaria, pero no reduce.

Por eso "no cambia de tamaño" o incluso crece. No es un bug, es cómo funciona tu algoritmo.

🔴 Problema 4: La UCA tiene <directories/> mal puesto
En la acción "Comprimir" no está <directories/>, así que ni siquiera aparecería sobre carpetas. Pero aunque lo añadieras, el binario fallaría igual (Problema 1).

✅ Soluciones
A) Arreglar el comando de xfce4-terminal
Edita ~/.config/Thunar/uca.xml y cambia las dos <command>:

Comprimir:

xml
<command>xfce4-terminal --hold -x bash -c '/usr/bin/tritos_compress -c -m ternary "%f" "%f.trc5"; echo; echo "Presiona Enter"; read'</command>
Descomprimir:

xml
<command>xfce4-terminal --hold -x bash -c 'out="${1%.trc5}"; /usr/bin/tritos_compress -d "$1" "$out"; echo; echo "Presiona Enter"; read' _ %f</command>
Ojo al cambio clave: -x en lugar de -e, y usar %f entre comillas dobles.

B) Para carpetas: empaquetar con tar primero
Como el binario no soporta carpetas, haz que la UCA empaquete con tar y luego comprima:

Comprimir carpeta:

xml
<command>xfce4-terminal --hold -x bash -c 'cd "$(dirname "%f")" && tar -cf "/tmp/$(basename "%f").tar" "$(basename "%f")" && /usr/bin/tritos_compress -c -m ternary "/tmp/$(basename "%f").tar" "%f.tar.trc5" && rm "/tmp/$(basename "%f").tar"; echo; read'</command>
Y añade <directories/> a la acción:

xml
<patterns>*</patterns>
<text-files/>
<image-files/>
<other-files/>
<directories/>
C) Asumir que tu formato expande, no comprime
Si tritos_compress es un experimento educativo (ternario ancestral, CRT), entonces es normal que expanda. No esperes ratios < 1. Es un formato de representación, no de compresión.
